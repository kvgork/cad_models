Personal CAD models (SO-101 arm, JeTank, gripper R&D), built with SolidCraft and kept in git.

These rules come from the Second Brain vault (`/home/koen/Documents/Vaults/Local/05-Wiki/research/`):

If a rule here conflicts with those notes, the notes win; update this file to match.

## Tools (pinned, see TOOLS.md; never upgrade without asking)

- SolidCraft 0.30.1 (`solidcraft-cli` in `~/.local/bin`). Format 48 files do not open in older builds. No nightly or RC builds for committed files.
- git with git-lfs (patterns in `.gitattributes`).

## Layout

```
<product>/README.md                    what it is, interfaces, print notes
<product>/cad/<PN>_<name>.json         command script: the source of truth (parametric)
<product>/cad/<PN>_<name>.sc           built design, regenerated from the script (LFS)
<product>/cad/<PN>_<name>.check.json   overlay: fit/clearance check run with --in <part>.sc
<product>/exports/<PN>_<name>_<REV>.{step,stl,3mf}   generated only; never hand-edit
<product>/exports/_superseded/         replaced exports are moved here, never deleted
<product>/tools/                       generator / analysis scripts (python), repo-relative paths
lib/<group>/<LIB-NNNN>_<name>.<ext> + SOURCE.md   vendor parts, READ-ONLY
tools/build.sh                         rebuild all (`--assemblies` runs overlays, ~10 min), then refresh print lists; tools/parts.py reads PARTS.md
tools/printlist.py                     writes each README's print list (qty per STL) + fastener BOM; `--check` fails if stale
tools/plates.py                        ready-to-slice plates <folder>/exports/plates/*.3mf (+ PNG), 256 mm bed; `--bed 180`
<product>/fasteners.json               fastener BOM source (screws, nuts, washers, inserts, spacers per position)
PARTS.md                               part register (PN, name, folder); TOOLS.md pinned versions
```

**Products with several design versions** get one folder per version, each a complete product (see `strandbeest_gripper/`):

```
<product>/README.md                    overview: version table + comparison
<product>/tools/                       generators/verifiers shared by all versions
<product>/v<N>[x]_<short-name>/        e.g. v2_dual-finger, v3a_pivot-jaws
    README.md  cad/  exports/  docs/   exports = the COMPLETE print kit for that version,
                                       shared parts included (LFS stores identical files once)
```

- A new version gets a new folder and a new assembly number. Earlier versions are left untouched.
- Parts that don't fit an earlier version get new part numbers; parts that do fit keep theirs.
- `tools/build.sh <product>/<version>` builds one version.

## Naming and revisions

- **File names are readable: `<PN>_<name>`**, where name is lower-case `a-z 0-9 -` from the Name column of `PARTS.md` (e.g. `GRIP-0015_link-j-hub.json`). There is never a revision in a native file name.
  - **User decision (2026-11-07):** this deliberately extends the vault rule "file name = part number". A bare code isn't readable.
  - Component and body names in assemblies use the same `<PN>_<name>` (+ `_F1`/`_F2` instance suffixes).
  - Generators get names from `tools/parts.py`, never typed by hand.
- **Part numbers:** `<PROJ>-<NNNN>`.
  - PROJ is `SO101`, `JTNK`, `GRIP` or `LIB`.
  - 0001–8999 are parts and 9000–9999 are assemblies.
  - Never reuse or renumber a part number.
- **New part number:** take the next free one from `PARTS.md`, add a row there **with a name and folder**, and tell the user it was allocated.
- **Print list (user rule 2026-11-07): every product / version README has one.** It says how many of each exported STL to print (file name, qty, part, material) and the total.
  - Generated by `tools/printlist.py` between `<!-- printlist:start/end -->` markers, never hand-written.
  - Quantities are counted from the assembly script's components (purchased `lib/` parts left out). Without an assembly it is 1 of each STL.
  - It fails if an export is missing from the assembly or the other way round. Run `tools/printlist.py --check` before every commit that touches exports.
- **Fastener BOM (user rule 2026-11-07): every product / version README has one.** It is generated from `<folder>/fasteners.json` (qty, where, items; `"approx": true` for washers) as a shopping list with totals plus a where-it-goes table.
  - Every screw, nut, washer, insert and spacer goes in it, with standard and length. Lengths come from the stack; mark unverified ones **NEEDS CHECK**.
  - If there are no fasteners, use `{"note": "No fasteners.", "lines": []}`. A missing file fails `--check`.
  - Never hand-write quantities in other README tables.
- **Print plate (user rule 2026-11-08): every product / version gets ready-to-slice plates** in `exports/plates/` (one `.3mf` per 256 × 256 bed, opens directly in Bambu Studio), generated by `tools/plates.py` from the print-list quantities; `build.sh` refreshes them. Mention the plate file in the README with the slicer notes (brim on tall, thin parts). **Normal (rigid) and TPU prints always on separate plates** (user rule 2026-11-08; grouped by the PARTS.md material).
- **Build plan with pictures (user request 2026-11-09):** an assembly README gets a step-by-step build plan, one picture per step rendered from the assembly. Use a `snapshot` script with `browser.visibility` false for parts not yet placed (`opacity=0` still draws edges) and `--body …:color=` for the new parts. Example: `strandbeest_gripper/tools/build_guide_v4b.py`. Include a part-dimension table (hole spacing from the generator, overall size measured on the STL) so parts can be told apart and checked (user request 2026-11-10).
- **Labels on existing parts** (v5): a debossed label keeps fit, so the part keeps its PN at the next revision (X2), used only by the new version; parts whose geometry doesn't change stay X1. After any later thickness change, re-check each label cut by its volume drop (a thinner z60 idler left its label cutting air).
- **Export name:** `<PN>_<name>_<REV>.<ext>`.
  - Unreleased print iterations are `X1`, `X2`, ….
  - A release takes a letter `A`, `B`, … (skip I O Q S X Z) and a git tag `<PN>/<REV>`.
  - A change that breaks fit or function with the old part gets a **new part number**. A change that keeps fit gets the next revision.
- **First command of every part script:** `document.metadata.set` with `part_number`, `description` (`NOUN, MODIFIER`, upper case), `revision` and `project`.
- **Assemblies:** set `component.metadata.set` (`part_number`, `description`, `bom_type`; `purchased` for `lib/` parts) on every component.
- **Names inside the model:** every feature, body, parameter and interface gets a name. Parameters get a comment that says the design intent.

## git

- `.sc .step .stp .stl .3mf .pdf .png` go through LFS (`.gitattributes`). Never commit before `git lfs env` works.
- `cad/*.json` use `diff merge=binary`: never let git auto-merge a command script.
- Commit **before** every export that will be printed; the export and the print log refer to that commit.
- Commit the script and its regenerated `.sc`/exports together.
- A SolidCraft version bump is its own commit.
- Ignored: `.agent-state/`, `*.bak`, `.~*.lock`.

## Modelling with SolidCraft

- **Script first.** Write or edit `<PN>.json`, then `tools/build.sh <product>` or `solidcraft-cli run cad/<PN>.json --save cad/<PN>.sc`.
  - Script paths are relative to the repo root.
  - Exports are steps in the script.
  - The `.sc` is never the master.
- **Parametric:** sizes, fits and positions are named parameters or expressions. No magic numbers in features.
- **Feature order:** fully define sketches, sketch on planes, origin-centred. Order is base → add/cut → holes → fillets and chamfers last.
- **Picks:** picking an edge or face by a coordinate breaks when dimensions change. Re-verify after every parameter change.
- **Assemblies and mechanisms:**
  - Ground one fixed reference.
  - Use `joint.create` (revolute, slider…) with limits.
  - Check motion with `joint.drive`, `motion.trace` and `joint.sweep` (collisions over the range).
- **`solidcraft-cli` subcommands:**
  - `run x.json --save x.sc [--in base.sc] [--results] [--json-out f]`
  - `eval x.sc` (bodies, bbox, volume, timeline errors)
  - `snapshot --in x.sc --out shot.png --view iso`
  - `commands` (the full catalog; grep it)
- **Fit checks:** `file.insert_step` the `lib/` part, place it with `occurrence.move` (`"<name>:1"`, `move_grounded: true`, a 3×4 `matrix`), then run `inspect.clearance` with `against: [...]`. Without `against` it checks 0 pairs. Against big vendor STEPs it is slow (~10 min) and can return `unchecked`; confirm those pairs with `inspect.section`.

## Verification loop (required before saying a part is done)

1. **Spec first.** Write down the envelope, interface positions and diameters, wall thickness and expected volume/bbox in the README or the request.
2. **Build in small stages:**
   - MCP: `batch` with `expect` (bodies, bbox, `volume_mm3`).
   - CLI: `eval` after each stage.
3. **Measure:** `measure`/`eval` after each stage. Get hole and boss positions from `body_topology` (cylinder origin, axis, radius), never from volume or a picture. A cut that leaves the volume unchanged missed.
4. **Parameter range:** `check_parameters` (MCP) or a `parameters.change` run confirms the model rebuilds across the parameter range.
5. **Fit and motion:** `inspect.clearance` / `inspect.section` for fit; `joint.sweep` for mechanisms.
6. **Screenshot last:** a sanity check, never proof. Never claim a dimension from an image.
7. **Export:** re-eval the export, report the numbers against the spec in a table, and say plainly what was not checked.

## Mechanisms, linkages and gears (lessons from strandbeest_gripper, 2026-11-07)

**Modelling the mechanism**
- **Analytic model first.** Write a small Python model, and have it assert a published reference value: `jansen.py` checks Ghassaei's stride / height / ymin, which also catches a wrong branch choice. Generate the assembly script from that model.
- **Build in place, then joint.** Build every link in place at one pose. Then add `joint.as_built` revolutes with `at: {point, z: [0,0,1]}`. Verify with `motion.trace` against the model: joint centres should agree within about 0.0001 mm.
- **Closed loops solve.** `joint.drive` handles them. A redundant parallelogram (two identical legs plus a bar pinned at both ends) loses the loop, so make one end a `pin_slot`. Do the same in the real part: a short slot keeps print tolerances from binding it.
- **Planar stacks need a layer plan.** Work it out over the motion range, including hubs, screw heads and nuts (`strandbeest_gripper/tools/layers.py`).
  - Fill empty layers in a pin column with printed hubs on the lower link, never loose spacers.
  - Limit the range with hard stops if you don't need a full turn: it needs fewer layers, and stops keep the mechanism away from toggle points.
- **Rigid tools on a rotating link swing with it.** Before lengthening a tip or jaw, compute its orientation over the stroke. The fix is a pivot or a parallel twin linkage, not a longer rigid part.
- **Mirror parts.** The mirror image of an asymmetric plate is a different part: give it its own part number and mark it (UP1/UP2) so it can't be assembled wrong. A planar linkage can also be assembled in its mirror branch, so put θ = 0 joint coordinates in the README.

**Gears**
- Generate involutes in the script.
- Use **z ≥ 17 teeth at 20° pressure angle**; z16 interfered with its partner.
- Tooth phase per mesh depends on the parity of the tooth count. Use a general mesh-phase formula (`gen_v3.mesh_phase`), never a rule that only works for even counts.
- **Test a phase formula on a mesh that is NOT on the line of centres.** The collinear case (offset 0) hid a sign error that made off-axis meshes overlap. After building, always check each mesh for overlap with `inspect.clearance`.
- Couple motion with `joint.gear`.
- **Mind what rides on top of a gear.** Hubs or pins on a gear sweep over its partner's tooth tips. Make driven gears 0.5 mm thinner (no flush tops), and check every mesh over the full turn, not just one tooth pitch.

**Verifying and inspecting**
- **A joint on the driven side of a motion link (`joint.screw`, `joint.rack_pinion`, `joint.gear` b) ignores `joint.drive`/`motion.trace` on itself, silently.** Drive the source joint, and make the verifier assert that the motion really happened (range reached), not just that nothing collided (finray, 2026-11-08).
- **Motion-link signs:** a wrong `reverse` flag looks perfect at the as-built pose and only shows once driven, as teeth overlapping. Always run the mesh clearance check at several driven positions.
- **`inspect.clearance` "unchecked" pairs are not "clear".** Pins in holes often come back unchecked (kernel intersect failed). The verifier must count them and fail on any it doesn't expect (v4b's J1 press fits were silently unchecked).
- **A new gear in the gear layer:** re-check every pin head / barb that sits under the lowest link; pin-vs-all clearance at 12 angles catches it (v5: J3 heads vs the z60 idler; v3b's screws were never checked).
- **Kernel boolean failures that depend on position:** overlap joined features generously (0.3 mm into a wider feature, same final shape), not by 0.01 mm.
- **`joint.sweep` has work budgets.**
  - Leave vendor STEPs and dense gear meshes out of big sweeps.
  - Split `occurrences`/`against` into chunks (gears 2 at a time, other parts 8).
  - Check gear meshes statically: `joint.drive` steps plus `inspect.clearance` over one tooth pitch.
- **Verify scripts assert result counts.** A `zip()` over a short result list or an empty trace passes silently. Generate the verify script from the same generator, never with hard-coded coordinates.
- **Check feature warnings in the GUI** (`inspect_design` over the bridge); `eval` doesn't show them. A join that only touches a face doesn't fuse, so make joined features overlap.
- **Renames and moves:** rebuild afterwards and compare every body's volume with the volumes from before.
- **Reloading in the GUI:** opening a file that is already open just switches to its tab. Ask the user to close it (without saving) first.

## FDM printability (defaults; calibrate per printer and material, then write the measured value back)

- **Walls:** `nozzle 0.4`, `line_w 0.45`, `layer_h 0.2`. Walls on the perimeter grid (0.9 / 1.35 / 1.8 mm); nothing under one perimeter.
- **Clearances:** `fdm_clearance 0.2` (sliding). Moving parts 0.3. Rotating pin holes for M3: Ø3.4 (ISO 273 medium).
  - **Printed pin in printed hole (user rule 2026-11-08): 0.10–0.15 mm play per side** (default 0.15, as a named parameter). Press fits on printed pins: 0.2 mm interference on the diameter.
- **Heat-set inserts:** M3 hole Ø4.0–4.2, blind, ≥ 1 mm deeper than the insert. Use inserts for anything unscrewed twice.
- **Orientation and overhangs:**
  - Chamfer bed-facing edges; don't fillet them.
  - Overhangs ≤ 45–60° without supports.
  - Don't grow snap hooks straight up off the bed.
- **Horizontal holes:** they print small; use a teardrop or a measured offset.
- **Elephant foot:** about 0.2 mm, handled by the slicer; don't also chamfer the same edge in CAD.
- **Strength:** more perimeters, not more infill.
- **Materials:**
  - PLA only for static fit checks.
  - PETG for links.
  - ASA/PETG next to servos (they run warm).
- **Part marking:** bold capitals ≥ 4 mm, debossed ≈ 0.6 mm on a top or low-stress face. Too small for text: dots or a bag label.
- **Printed fasteners (strandbeest v4a/v4b, 2026-11-08):**
  - Keep printed pins inside the envelope of the screws/nuts they replace (`layers.py`): the existing parts are then reused unchanged.
  - Pins print lying down on a 0.25 mm D-flat (layers along the pin). A snap pin's slot plane must stand upright in that pose so it doesn't bridge.
  - Snap barb: shoulder 0.2 mm above the stack top, 0.3 mm catch per side, 0.8 mm slot. One-piece snap pins replace pin + cap: half the pin part count.
- **Variants of one part in one assembly** (finray fingers): mount one, park the others rigid on the base so the print list counts them. Keep the mounting outline identical across variants so one mounted check covers all.
- **Plate generator lessons:** pick the bed face by real mesh contact area, not convex-hull area (a hull face can span a recess). (x, y) → (y, −x) is a 90° turn, not a mirror: never flip triangle winding for it. Check every placed object's signed volume against its STL.
- **First print on a new printer or material:** print a coupon first.

## SolidCraft MCP server

- **Tools:** `skill_reference {"skill":"solidcraft-modeling"}` first, then `inspect_design`, `batch`, `measure`, `body_topology`, `check_parameters`, `screenshot`.
- **Path sandbox:** MCP `open` and `save` only work inside `/tmp/solidcraft-mcp-<pid>-*`.
  - Build with the CLI in the repo, then copy the `.sc` there to view it in the GUI.
  - To fix this permanently, start the server with `--allow-path /mnt/data/workspaces/cad_models`.
- **Live GUI:** port in `~/.local/share/solidcraft/control/current.port`, token in `<port>.token`. Bridge with `solidcraft-cli mcp --connect 127.0.0.1:<port> --token <t>`.

## Hard limits

- Never modify anything under `lib/`, `exports/_superseded/` or a released (tagged) revision.
- Never call `new_design` over an existing file, and never use `--allow-any-path`.
- Never upload CAD files to external services.
- Never start a print. Uploads to a printer use auto-start off; a human starts every print.
- Tolerances, fits and DFM sign-off are drafts until printed and measured. Mark them **NEEDS PRINT TEST** in the README.
- Before moving or renaming files: make a backup, or make sure the tree is committed. Then rebuild and compare volume and bbox per part.
